Tổng Hợp "Bẫy" Hay Gặp Trong Đề Thi NoSQL

Các lỗi kinh điển về Mảng lồng, $elemMatch, $unwind, $addFields, $lookup và Cassandra Keys/Indexes.

Bẫy & Mẹo Cassandra CQL Cassandra
  • Bẫy ORDER BY không đúng thứ tự Clustering Key: Trong CQL, nếu Primary Key là `((dept_id), created_at, user_id)`, bạn KHÔNG THỂ `ORDER BY user_id` nếu chưa chỉ định `created_at` trong mệnh đề `WHERE` hoặc `ORDER BY`.
  • Truy vấn trên Collections (SET, LIST, MAP): Để lọc phần tử trong Set/List phải tạo Index: CREATE INDEX ON tbl(CONTAINS tags), sau đó query dùng WHERE tags CONTAINS 'val'. Đối với MAP thì dùng KEYS(map_col) hoặc VALUES(map_col).
  • Bẫy Materialized View thiếu Primary Key gốc: MV bắt buộc phải chứa TOÀN BỘ các cột thuộc Primary Key của bảng gốc, cộng thêm cột mới được dùng làm PK cho MV.
Bẫy & Mẹo MongoDB Aggregation & Mảng MongoDB
  • Bẫy Mảng đơn vs Mảng Object với $elemMatch: Với mảng đơn giá trị [10, 20, 30]: dùng { scores: { $elemMatch: { $gte: 15, $lte: 25 } } }. Với mảng Object: dùng { items: { $elemMatch: { price: { $gt: 100 }, status: 'OK' } } }. Nếu KHÔNG dùng $elemMatch, MongoDB sẽ tìm document mà điều kiện 1 thỏa mãn ở Object A, điều kiện 2 thỏa mãn ở Object B (BỊ SAI)!
  • Phân biệt $addFields / $set vs $project: $addFields (hoặc $set) **giữ lại toàn bộ** các trường cũ và chỉ bổ sung/ghi đè trường mới. Còn $project sẽ **xóa sạch** các trường khác ngoại trừ những trường bạn khai báo `1`.
  • Bẫy $unwind làm nhân bản document & biến mảng trong $group: Khi $unwind mảng `items`, mỗi phần tử trở thành 1 document riêng lẻ. Nếu muốn gom nhóm lại mảng ban đầu sau khi biến đổi, hãy dùng accumulator $push hoặc $addToSet (loại bỏ trùng lặp) trong stage $group!

Tra Cứu Nhanh Các Toán Tử Aggregation Tần Suất Thi Cao

Mục đích yêu cầu đề bài Toán tử / Stage tương ứng Cú pháp ví dụ điển hình
Tách mảng ra thành các bản ghi riêng lẻ $unwind { $unwind: { path: "$items", preserveNullAndEmptyArrays: true } }
Tạo thêm trường mới (Tính toán tổng, nhân chia...) $addFields / $set { $addFields: { totalItemPrice: { $multiply: ["$price", "$quantity"] } } }
Lọc 1 phần tử cụ thể bên trong mảng khi trả về $filter / $elemMatch (projection) { $project: { items: { $filter: { input: "$items", as: "i", cond: { $gte: ["$$i.score", 5] } } } } }
Kết nối 2 Collection (JOIN) kèm điều kiện lọc $lookup với Pipeline lồng { $lookup: { from: "products", let: { pId: "$productId" }, pipeline: [{ $match: { $expr: { $eq: ["$_id", "$$pId"] } } }], as: "productDetails" } }
Gom nhóm & Thu thập danh sách giá trị không trùng $group + $addToSet { $group: { _id: "$category", uniqueTags: { $addToSet: "$tag" } } }

Các Khung Mẫu Cú Pháp Phức Tạp (Thi Tự Luận & Thực Hành)

Các mẫu Pipeline chuẩn mẫu xử lý mảng lồng, $unwind, $addFields và $lookup nâng cao.

1. Pipeline Mảng Lồng: $unwind $\rightarrow$ $addFields $\rightarrow$ $group TÍNH TOÁN THEO CHI TIẾT ITEM 

db.orders.aggregate([
  // 1. Tách mảng items thành từng document nhỏ
  { $unwind: "$items" },
  
  // 2. Tính thành tiền từng item (price * quantity)
  { $addFields: {
      "items.subtotal": { $multiply: ["$items.price", "$items.qty"] }
  }},
  
  // 3. Gom nhóm theo Đơn hàng để tính tổng tiền & tạo lại danh sách items
  { $group: {
      _id: "$_id",
      customerId: { $first: "$customerId" },
      totalOrderAmount: { $sum: "$items.subtotal" },
      calculatedItems: { $push: "$items" }
  }},
  
  // 4. Lọc đơn hàng có tổng tiền > 500
  { $match: { totalOrderAmount: { $gt: 500 } } }
]);

2. Khung $lookup với Pipeline Lồng (Custom Join) JOIN CÓ ĐIỀU KIỆN LỌC 

db.orders.aggregate([
  {
    $lookup: {
      from: "products",
      let: { order_prod_id: "$productId" }, // Khai báo biến từ doc hiện tại
      pipeline: [
        {
          $match: {
            $expr: {
              $and: [
                { $eq: ["$_id", "$$order_prod_id"] },
                { $eq: ["$is_active", true] } // Chỉ lấy sản phẩm còn kinh doanh
              ]
            }
          }
        },
        { $project: { name: 1, price: 1, category: 1 } }
      ],
      as: "product_info"
    }
  },
  // Flatten mảng kết quả join
  { $unwind: { path: "$product_info", preserveNullAndEmptyArrays: true } }
]);

PHẦN 1: BÀI TẬP CASSANDRA (MV, Collections & Bẫy Query)

Các bài toán phân vùng, Materialized View và chỉ mục dữ liệu tập hợp

Cassandra
Câu 1: Năm học 2024 – 2025 có bao nhiêu độc giả làm thẻ mới?
Đáp án

💡 Phân tích: Lọc theo academic_year $\rightarrow$ Đưa academic_year làm Partition Key.

CREATE MATERIALIZED VIEW IF NOT EXISTS mv_readers_by_academic_year AS
    SELECT academic_year, reader_id, reader_name, created_date
    FROM readers
    WHERE academic_year IS NOT NULL AND reader_id IS NOT NULL
    PRIMARY KEY (academic_year, reader_id);

-- Truy vấn:
SELECT COUNT(*) AS total_new_readers 
FROM mv_readers_by_academic_year 
WHERE academic_year = '2024-2025';
Câu 2 (Nâng cao): Cho bảng `student_courses` chứa trường `subjects_enrolled set`. Hãy viết câu lệnh tạo Index và truy vấn tìm tất cả sinh viên đăng ký môn `'NoSQL'`?
Đáp án

💡 Phân tích: Không thể tìm trong tập hợp `SET` bằng dấu `=` mà phải dùng chỉ mục `CONTAINS`.

-- Bước 1: Tạo Secondary Index trên tập hợp SET
CREATE INDEX idx_subjects ON student_courses(CONTAINS subjects_enrolled);

-- Bước 2: Thực hiện truy vấn lọc
SELECT student_id, student_name, subjects_enrolled 
FROM student_courses 
WHERE subjects_enrolled CONTAINS 'NoSQL';

PHẦN 2: ĐỀ MONGODB (MẢNG LỒNG, $elemMatch, $unwind, $addFields, $lookup)

Chuyên đề câu hỏi gài bẫy xử lý mảng phức tạp & Pipeline Aggregation

MongoDB
Câu 1 (Mảng Object & $elemMatch): Cho collection `orders` với cấu trúc `items: [{ p_id: 'A', price: 10, qty: 2 }, { p_id: 'B', price: 50, qty: 1 }]`. Tìm các đơn hàng chứa CÙNG MỘT sản phẩm có `price > 20` VÀ `qty >= 2`.
Đáp án

💡 Giải thích bẫy: Nếu viết `{ "items.price": { $gt: 20 }, "items.qty": { $gte: 2 } }`, nó sẽ trả về cả đơn hàng có sản phẩm A giá 10 (qty 2) và sản phẩm B giá 50 (qty 1). Để ép điều kiện vào CÙNG 1 sản phẩm, BẮT BUỘC dùng $elemMatch.

db.orders.find({
  items: { 
    $elemMatch: { 
      price: { $gt: 20 }, 
      qty: { $gte: 2 } 
    } 
  }
});
Câu 2 ($unwind & $addFields): Cho collection `orders`. Viết Pipeline: 1. Tách mảng `items`. 2. Thêm trường `subtotal = items.price * items.quantity`. 3. Tính tổng thành tiền `totalAmount` cho từng đơn hàng và giữ lại danh sách các `subtotal` trong mảng.
Đáp án 
db.orders.aggregate([
  // Bước 1: Tách mảng items (giữ lại doc nếu mảng rỗng)
  { $unwind: { path: "$items", preserveNullAndEmptyArrays: true } },

  // Bước 2: Dùng $addFields tính giá tiền nhân số lượng
  { $addFields: {
      "items.subtotal": { $multiply: ["$items.price", "$items.quantity"] }
  }},

  // Bước 3: Gom nhóm theo _id đơn hàng
  { $group: {
      _id: "$_id",
      orderDate: { $first: "$orderDate" },
      totalAmount: { $sum: "$items.subtotal" },
      subtotalList: { $push: "$items.subtotal" }
  }}
]);
Câu 3 (So sánh 2 trường trên 1 document bằng $expr): Tìm các sản phẩm trong `products` có giá bán thực tế (`salePrice`) THẤP HƠN giá vốn (`costPrice`).
Đáp án

💡 Bẫy: Không thể viết `{ salePrice: { $lt: "$costPrice" } }` trong `.find()` thông thường vì nó sẽ coi `"$costPrice"` là 1 chuỗi string tĩnh. BẮT BUỘC dùng toán tử biểu thức $expr.

db.products.find({
  $expr: {
    $lt: ["$salePrice", "$costPrice"]
  }
});
Câu 4 ($lookup + $unwind + $group): Kết nối bảng `users` và `orders`. Thống kê tổng số tiền đã chi tiêu của từng người dùng (chỉ tính đơn `"DELIVERED"`), hiển thị `userName` và `totalSpent`.
Đáp án 
db.users.aggregate([
  // Bước 1: Lookup nối sang bảng orders
  {
    $lookup: {
      from: "orders",
      localField: "_id",
      foreignField: "userId",
      as: "userOrders"
    }
  },
  // Bước 2: Tách mảng orders
  { $unwind: { path: "$userOrders", preserveNullAndEmptyArrays: false } },

  // Bước 3: Lọc đơn hàng DELIVERED
  { $match: { "userOrders.status": "DELIVERED" } },

  // Bước 4: Gom nhóm theo User
  {
    $group: {
      _id: "$_id",
      userName: { $first: "$name" },
      totalSpent: { $sum: "$userOrders.amount" }
    }
  },
  { $sort: { totalSpent: -1 } }
]);

01 Các Stage chính

02 Toán tử điều kiện

$eq — Bằng
$ne — Khác
$gt / $gte — > / ≥
$lt / $lte — < / ≤
$in — Thuộc danh sách
$nin — Không thuộc
$and / $or — AND / OR
$not — Phủ định
$exists — Field tồn tại, ví dụ {email: {$exists: true}}

03 Accumulator trong $group

$sum — Tổng / đếm
{ $sum: "$diem" }
$sum: 1 — Đếm document
$avg — Trung bình
$max / $min — Lớn nhất / nhỏ nhất
$first / $last — Phần tử đầu / cuối
$push — Gom thành mảng
$addToSet — Gom mảng và tự loại giá trị trùng

04–05 Mảng & xử lý giá trị

{ $unwind: "$monHoc" } tách từng phần tử mảng thành một document riêng.

preserveNullAndEmptyArrays: true giữ document khi mảng rỗng, null hoặc không tồn tại.

$add — Cộng$subtract — Trừ$multiply — Nhân$divide — Chia$mod — Chia lấy dư$concat — Nối chuỗi$size — Số phần tử mảng$arrayElemAt — Lấy phần tử theo vị trí$cond — IF / ELSE$expr — Biểu thức điều kiện

06 $lookup — JOIN collection

from
Collection muốn JOIN
localField
Field ở collection hiện tại
foreignField
Field ở collection bên kia

Tên field chứa kết quả JOIN
db.sinhvien.aggregate([
  {
    $lookup: {
      from: "monhoc",
      localField: "maMH",
      foreignField: "maMH",
      as: "monHoc"
    }
  }
])

07–08 $count, $sum: 1 và "$field"

  • $count: đếm tổng document sau stage trước, ví dụ { $count: "soLuong" }.
  • $sum: 1: đếm document theo từng nhóm.
  • { $sum: "$diem" }: tính tổng một field.
  • "$diem" là giá trị field trong document hiện tại; không có $ thì là chuỗi tĩnh.

09–10 Pipeline mẫu & thứ tự ưu tiên

Đọc pipeline: lọc → tách mảng → gom nhóm → đếm/tính toán → sắp xếp.

$match→$group→$project→$unwind→$lookup→$sort→$count → $sum → $avg → $max → $min → $first → $last → $push → $addToSet → $expr → $size → $in → $gte/$gt/$lte/$lt
